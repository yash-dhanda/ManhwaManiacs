## Unresolved

### MOBILE-6: the web scrims cannot follow the bar as written

The round-2 text is in place everywhere it should be: §2.1.4 `scrim.head` and `scrim.sole` (l. 110–111), §2.8.3 (l. 493–494), §3.3 "Heights are minimums" (l. 648), the §7 intro Heights bullet, §7.13 Height, §8.14.3 running head and folio bar (l. 2190, 2196) and the §15.7 over-art test rows (l. 4411). The fixed "safe area + 88 px phone" and "bottom 128 px + safe area" wording is gone. The Flutter construction is sound: `Positioned(bottom: -fade)` in `Stack(clipBehavior: Clip.none)`, `LayoutBuilder` bar = `constraints.maxHeight − fade`, stops `[0, b, b + (1 − kScrimStops[i]) × f …]` run monotonically from b to 1.

The web half has two defects:

1. **The `var()` resolves on `<html>`, not on the bar.** §2.8 (l. 337) declares every `--mm-*` property under `[data-skin="cinematic"]`, i.e. on `<html>`. §2.8.3 makes `--mm-scrim-head` and `--mm-scrim-sole` "complete `background-image` values" that contain `var(--scrim-bar)` and `var(--scrim-fade)`. A custom property's `var()` references are substituted when that property is computed, on the element that declares it (CSS Custom Properties Level 1, computed value). On `<html>`, `--scrim-bar` and `--scrim-fade` are undefined, so `--mm-scrim-head` is invalid at computed-value time and inherits as the guaranteed-invalid value. The bar's own `--scrim-bar: calc(100% - var(--scrim-fade))` never reaches it, and `background-image: var(--mm-scrim-head)` on the `::before` falls back to `none`. The sentence "so the flat part follows the bar's rendered height with no measuring" is therefore false on the web, and the running head, the reader folio bar and the Listen transport lose their scrim over art. `scrim.foot` has the same flaw through `--scrim-solid-at` (§2.8.3 l. 491). It is outside this lens, but it has the same root and should get the same fix.
2. **`--scrim-fade` is never given a value.** Only `var(--scrim-fade)` appears. The 44 px phone head fade, the 64 px desktop head fade and the 64 px sole fade exist only in the prose.

**Fix (§2.8.3 `scrim.head`, `scrim.sole` and, for the same reason, `scrim.foot`).** Keep the gradient out of the `[data-skin]` block and let the utility emit it, so every `var()` resolves on the element that paints it:
- `design/build.mjs` writes `@utility scrim-head { background-image: linear-gradient(to bottom, rgb(0 0 0/.88) 0 calc(100% - var(--scrim-fade)), <the 13 stops at calc(100% - var(--scrim-fade) + (1 − stop) × var(--scrim-fade)) with alpha .88 × alpha>); }` into `theme.generated.css`. `scrim-sole` is the same `to top` with .90. `--scrim-bar` is no longer needed, because `100%` in a stop already resolves against the `::before`'s own height (bar + fade).
- The bar applies it as `before:scrim-head` (the `::before` keeps `position: absolute; inset: 0 0 calc(-1 * var(--scrim-fade)) 0; z-index: -1; pointer-events: none`, and `inset: calc(-1 * var(--scrim-fade)) 0 0 0` for the sole) and sets `--scrim-fade`: `44px` on the phone running head, `64px` from 768 px, `64px` on the folio bar and the Listen transport.
- Drop `--mm-scrim-head` and `--mm-scrim-sole` from the `[data-skin]` block, or keep them only as documentation of the stop list. `scrim-foot` moves into its utility the same way, reading `--scrim-solid-at` on the painting element.
