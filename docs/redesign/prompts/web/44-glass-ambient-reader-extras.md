### C. The soundscape engine (§9.4.2, §6, §15.2)

Pure recipes in `frontend/src/skins/glass/soundscape-recipes.ts` (+ `soundscape-recipes.test.ts`); the engine in `frontend/src/skins/glass/soundscape.ts`. If `web/29` already created `soundscape.ts` with the audio-session state machine, extend that file; if its state machine lives in another file, keep it there and import it.

C1. **One `AudioContext`**, created lazily and resumed inside the user's tap that starts a scene (browsers refuse audio without a gesture). Graph: per scene three layer chains (Bed, Detail, Tone), each `procedural gain` + `recorded gain` → `layer GainNode` (the mixer value) → `master GainNode` (`volumeDb`, default −12 dB, `gain = 10^(dB/20)`, −12 dB → 0.251) → `duck GainNode` → `destination`. One `AnalyserNode` per layer (`fftSize` 32) feeds the level bars.
C2. **Procedural layers** (the table's last column; "always available, no files"). Noise sources are 4 s `AudioBuffer`s at the context's sample rate, looped: white noise; pink noise by Paul Kellet's filter over white; brown noise by a leaky integrator (`b = (b + 0.02 × white) / 1.02`, then × 3.5). Each procedural layer is normalised to −24 dBFS RMS before its gains unless the table gives a level. Event parts (droplet ticks, crackles, bursts) are scheduled live by a look-ahead scheduler (a 50 ms `setInterval` that schedules every event falling in the next 150 ms of `AudioContext.currentTime`, Poisson arrivals from a seeded `mulberry32` PRNG), so nothing repeats audibly. Mapping, exactly:

   | Scene | Bed | Detail | Tone |
   |---|---|---|---|
   | Rain | pink noise → high-pass 400 Hz → low-pass 6 kHz | droplet ticks: sine 2–4 kHz (uniform), 4 ms with a 1 ms attack and exponential decay, 8–20 per second (the rate itself wanders between 8 and 20 on a 0.1 Hz random walk), each through a `StereoPannerNode` at a uniform pan −0.8 to 0.8 | brown noise → low-pass 200 Hz at −24 dB |
   | Wind | brown noise → band-pass 300 Hz, Q 0.7, the centre modulated ±150 Hz by a 0.08 Hz sine LFO into the filter's `frequency`; a 0.05 Hz LFO on the layer gain, depth 0.4 | filtered noise bursts: white noise → band-pass 1.2 kHz Q 1, 40–120 ms long, Poisson rate 0.5 per second | silent in the built-in version |
   | Ocean | brown noise → low-pass 900 Hz; a 0.1 Hz LFO on the layer gain, depth 0.7 | white noise → high-pass 2 kHz whose gain follows the same 0.1 Hz swell delayed by 1.5 s (a second LFO at the same rate, phase −54°) | silent in the built-in version |
   | Hearth | brown noise → low-pass 1.2 kHz at −18 dB | crackles: 3–8 ms white-noise bursts → band-pass 3 kHz Q 2, Poisson rate 6 per second | silent in the built-in version |
   | Stream | pink noise → band-pass 1.8 kHz, Q 1.2, with a 7 Hz LFO on the layer gain, depth 0.15 | silent in the built-in version | silent in the built-in version |
   | Deep | sines at 55 Hz and 82.41 Hz (A1 + E2), each detuned by a 0.03 Hz LFO of ±4 cents (the chorus), plus pink noise → low-pass 300 Hz at −18 dB | silent in the built-in version | silent in the built-in version |

   A layer that is silent in the built-in version still has its mixer slider, which controls its recorded layer once that arrives. Tests: the recipe table covers 6 scenes × 3 layers; the scheduler at rate 6/s over 10 s of virtual time yields 45–75 events and never schedules an event before the window start; the same seed gives the same events; `dbToGain(-12) ≈ 0.2512`, `dbToGain(-30) ≈ 0.0316`.
C3. **Recorded layers** (primary when available). Format: `new Audio().canPlayType('audio/ogg; codecs="opus"') === ""` → `.m4a`, otherwise `.ogg`, checked once before any `decodeAudioData`. URL `/api/app/soundscapes/glass-{scene}-{layer}.{ext}` (the id spelling of glass §9.4.2 and §15.5; `backend/07` maps it onto `backend/media/soundscapes/glass/{scene}-{layer}.{ext}` and also answers the older `/app/soundscapes/glass/{scene}-{layer}.{ext}` alias, which no client uses). Fetch only the playing scene's three layers, on first play, through Cache Storage `mm-soundscapes-v1` (`caches.open`, `match`, else `fetch` and `put` on a 200); decode; play as `AudioBufferSourceNode` with `loop = true`. When a layer is decoded, cross-fade it in over 2 s against its procedural counterpart (`linearRampToValueAtTime` on both gains), then stop that procedural layer's nodes and scheduler. A 404, a network error or a decode error keeps the procedural layer playing.
C4. **Starting** (§9.4.2 Starting). The procedural version starts at 0 ms on the tap; the master fades in over 3 s; the scene's recorded layers replace their procedural layers as they arrive. Offline with nothing cached, or any recorded layer failing: the scene keeps its procedural layers and the scene orb shows the `cloud-slash` badge with the tooltip "Playing the built-in version" (not shown during the first 2 s while files may still arrive).
C5. **Mixing rules** (§9.4.2). Fade in 3 s, fade out 1.5 s. While narration plays, the duck gain ramps to −12 dB (0.251) over 400 ms and back over 400 ms when it stops; with "Lower under narration" off, the soundscape pauses (fade out 1.5 s, then `suspend()` if nothing else plays through this context) and resumes with the 3 s fade when narration stops. It follows the sleep timer's 8 s fade (`web/37`) and stops with it. Leaving the reader: fade out 1.5 s and pause; returning to a reader in the same tab: resume the same scene with the 3 s fade. `visibilitychange` to hidden: fade out 1.5 s and suspend unless narration is playing; visible again: resume. Narration state comes from the one signal `web/37`'s player uses (`grep -rln "narration" frontend/src/features frontend/src/skins/glass --include=*.ts*`); if that signal lives only inside a Glass component, lift it into the audio-session state machine, not into a second store.
C6. **Audio session** (§6). The engine requests states from the state machine and never sets them itself: `idle → soundscape` on start (`navigator.audioSession.type = "playback"` where `navigator.audioSession` exists), `soundscape → narration` when narration starts, `narration → soundscape` when it stops with a scene still on, back to `idle` (`"ambient"`) 1.5 s after the last fade-out. UI sounds (`sounds.ts`) stay silent in `soundscape` and `narration`. The web cannot detect another app's music, so the "muted (music playing)" state and its toast do not exist on the web.
C7. **Match the story** (§9.4.2). `matchScene(genres)` walks the series' own genre list in order, lowercased, and returns the first hit: horror, thriller, mystery, psychological → Rain; romance, slice of life, comedy, drama, historical → Hearth; fantasy, isekai, school, supernatural → Stream; adventure, sports → Ocean; action, martial arts, murim, military → Wind; sci-fi, mecha, cyberpunk, space → Deep; nothing → Rain. Order of precedence when the reader opens a scene: a remembered per-series `soundscape` → Match the story (when on) → the default scene. Tests cover every genre word above and the fallback.
C8. **States** (§9.4.2 States): `off`, `starting` (procedural, first 2 s), `playing-recorded` (all non-silent layers recorded), `playing-builtin` (at least one layer on its procedural fallback after 2 s), `paused`, `ducked`, `unavailable` (the context cannot be created or resumed: toast "Couldn't start the soundscape", state back to `off`). A `useSoundscape()` hook exposes `{ state, scene, matchedScene, levels, mix, volumeDb }` and the commands `start(scene)`, `stop()`, `setMix(layer, v)`, `setVolume(db)`.
C9. **18+ purge**: register a stop with the Glass shell's `purgeMatureLocal()` step 1 when the open series is mature.
