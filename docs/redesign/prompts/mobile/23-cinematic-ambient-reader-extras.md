## Goal

Build new feature 4 for the Cinematic skin in both Flutter readers (iOS and Android), exactly as `docs/redesign/cinematic/DESIGN.md` §9.4 specifies. **Auto-scroll "projection speed"**: 0.50–3.00× of 60 px/s at a 1080 px viewport in the manga strip and of the profile's measured words-per-minute pace in the novel scroll layout, a 400 ms speed ramp, the floating chip, the speed ruler sheet, pace by dialogue from the words on screen via `GET /ocr/chapter`, resume after release, and mutual exclusion with Listen. **The soundscape "house sound"**: the eight loops fetched once from `GET /app/soundscapes/{id}.{ogg|m4a}` into an app file cache and played on a second `just_audio` player under the §6 audio-session policy, with a 2000 ms fade in, a 600 ms fade out and ducking to 30 % under narration. **The panel-by-panel guided view**: panel detection in `mobile/lib/features/reader/engine/` in the same `compute()` isolate as page tint on a 360 px wide decode one page ahead, the `design/panel-vectors.json` parity cases in `panels_test.dart`, the new skin-neutral engine commands `setCamera` and `pageToViewport`, the Dolly between panels, the words-per-panel hold, `POST /reader/panels` on exit. **Page-tinted chrome**: `features/reader/engine/page_tint.dart` (a 16 × 16 `ResizeImage` decode read in `compute()`, exposing `pageTint`), the `design/tint-vectors.json` parity cases, `TweenAnimationBuilder` colour dissolves, `POST /reader/page-tints` on exit. Every entry point and state of §9.4.5 is delivered. Everything that is engine work lands skin-neutral in `mobile/lib/features/reader/` (and `features/novels/`) so the Glass readers (`mobile/34`, `mobile/35`, `mobile/44`) reuse it; everything visual lands in the Cinematic skin. No ScreenId changes in this step. The web session runs the web twin in parallel and shares the two parity files with you; do not touch `frontend/`.

## Scope: deliver every item below

Engine work (A) is skin-neutral: it takes durations, curves and springs as parameters and imports nothing from `lib/skins/`. The Cinematic UI (B–F) uses only engine state and commands and passes its own tokens (`context.cine.durRack`, `CineCurves.turn`, …).

### A. Engine work (`mobile/lib/features/reader/engine/`, no pixels)

A test under `mobile/test/features/reader/engine/` beside every module, except the tint parity test, which lives in the file the contract names.

A1. **`page_tint.dart`**: `Hls hls(int r, int g, int b)` (Python `colorsys` HLS on the 8-bit values divided by 255: L = (max + min) / 2; S = 0 when max = min, else (max − min) / (max + min) when L ≤ 0.5, else (max − min) / (2 − max − min)); `String? pickPageSeed(Uint8List rgba)` implementing §2.1.5 exactly (keep pixels with 0.10 < L < 0.90, strict; the seed is the kept pixel with the highest S, ties to the first in row-major order; greyscale, returning `null`, when no kept pixel has S ≥ 0.08 or none is kept; the result upper-case `#RRGGBB`); `TintTracker` (pure): fed a `seed | null` per sampled page it returns the chrome's tint source: the new seed for a chromatic page, the previous one for a greyscale page, and `cover` after **6 consecutive greyscale pages** until a chromatic page arrives. **Parity**: `mobile/test/skins/cinematic/tint_test.dart` (mobile/04's file, beside its 1,440-case contrast loop) gains a block that reads `File('../design/tint-vectors.json')` (the test runs from `mobile/`) and asserts `pickPageSeed` returns every `expected` of the 48 samples. `page_tint_test.dart` covers `TintTracker` (5 greyscale pages keep the colour, the 6th switches to `cover`, a chromatic page switches back).
A2. **`panels.dart`**: `Uint8List luminanceOf(Uint8List rgba)` (L = (0.2126 R + 0.7152 G + 0.0722 B) / 255 on 8-bit values, stored as 0–255), `List<PanelRect> detectPanels(Uint8List lum, int width, int height, PanelDirection direction)` in px at the analysis width, implementing §9.4.3 steps 1–7 and the three A0 interpretations: a row (or, within a band, a column) is a gutter line when ≥ 98 % of its pixels have L > 0.92 or ≥ 98 % have L < 0.06; a gutter is a run of ≥ 12 gutter lines; content runs between gutters (shorter gutter runs stay inside content) become bands, each rect taking the band's full height; each band is split once at its vertical gutters, except on a strip page (height / width > 2), where each band is one rect across the full width; rects under 48 px on either side are dropped; order top to bottom, then left to right, or right to left for `rtl`. `toPageFractions(rects, width, height)` for the manifest shape. **`panels_test.dart`** (`mobile/test/features/reader/engine/`) reads `File('../design/panel-vectors.json')` and each PNG through a 20-line test-only decoder (check the signature, read IHDR, concatenate the IDAT data, `ZLibCodec().decode` it, assert each row's filter byte is 0, strip it) and asserts exact equality with `expected` for all 24 cases.
A3. **The analysis isolate** (`page_analysis.dart`): `analysePage({ImageProvider? tintPage, ImageProvider? panelPage, required PanelDirection direction})` resolves `ResizeImage(tintPage, width: 16, height: 16, policy: ResizeImagePolicy.exact)` and `ResizeImage(panelPage, width: 360)` (height proportional), reads each with `toByteData(format: ui.ImageByteFormat.rawRgba)`, disposes the `ui.Image`s and **evicts both `ResizeImage` keys from `PaintingBinding.instance.imageCache`** right away (so analysis never counts against the engine's 64 MB decode budget and never touches the 120 Hz strip's cached pages), then runs one `compute(runAnalysis, AnalysisRequest(tintRgba, panelRgba, panelWidth, panelHeight, direction))` that returns `{seed?, tintFailed?, panels?, panelsFailed?}`. The tint for page n and the panels for page n + 1 travel in the **same** `compute` call, so a 10 s continuous scroll makes at most 17 calls (a fake-clock test counts them). A decode failure returns `tintFailed` / `panelsFailed` (the cover-colour fallback of §9.4.5).
A4. **Engine duties** (in `ReaderEngine` / `ReaderEngineState`; the §15.4 list):
   - **Page tint**: `pageTint` (`PageTintSource.page(seed)`, `PageTintSource.cover`, or `null` when page tint is off or nothing is sampled yet). The manifest's `pages[].tint` is used first (tinted from frame 0), then the saved chapter's stored tint (A4 last bullet); otherwise the page under the reading line (mobile/13's `pageAtReadingLine()`: 38 % from the top of the viewport in the strip; the current page in paged and guided layouts) is sampled when it changes and has decoded, **at most one sample per 600 ms** (a parameter the skin fills with `durSampleTint`), through `TintTracker`. Tint failures use the cover source.
   - **Panel detection**: `panels` (`Map<int, PanelsState>`: `found(List<PanelRect> fractions)`, `finding`, `none`); the manifest's `pages[].panels` first (an empty list means `none`), then the saved chapter's stored panels, then analysis **one page ahead** of the reading position, riding in A3's tint calls; entering guided view on a page with no result analyses that page at once (`finding` meanwhile).
   - **Words on screen**: `wordsOnScreen` (`int?`) while pace by dialogue is on and `ocrChapterTextProvider` has text for the chapter (null otherwise): every 250 ms, the count of whitespace-separated words in OCR boxes (through mobile/13's `ocr_boxes.dart`) whose centres, mapped by `pageToViewport`, fall inside the viewport. Pure counting in `words.dart` (`wordsInViewport(boxesByPage, toViewport, Rect viewport)`, `wordsInRect(boxes, Rect rect)`) with a test.
   - **Words per panel**: `wordsInPanel(int page, int panelIndex)` for the guided hold.
   - **Completion events**: `chapterCompleted` exists (mobile/12); reuse it.
   - **Exit reports** (§2.1.5, §9.4.3 Cache): on chapter exit (a chapter change inside the reader, the engine's dispose, and `AppLifecycleState.paused`), post the chapter's new samples once: `POST /reader/page-tints {source_id, series_key, chapter_key, tints: [{page, hex}]}` (greyscale pages omitted) and `POST /reader/panels {source_id, series_key, chapter_key, pages: [{page, panels}]}` (panels in page fractions, an empty list for `none`), fire and forget through the reader repository, skipped when `network_connectivity.dart` reports offline and when nothing new was sampled since the last post. For a chapter read from the saved copy, also store the values on the device: add nullable `tint` (TEXT) and `panels` (TEXT, JSON) columns to the `saved_pages` table through `downloads_db.dart`'s `_migrate` with the version constant raised by one (idempotent like the file's other migrations: skip each `ALTER TABLE … ADD COLUMN` when the column exists), read them when the saved copy opens, and write them on exit. Store tests: the upgrade from the previous version, the downgrade-reopen case the file already guards, the round trip.
A5. **Camera commands** (glass §15.4 rows; both skins): `setCamera(CameraTarget rect /* page + x, y, w, h in page fractions */, {Duration? duration, Curve? curve, SpringDescription? spring, Offset? velocity})` translates and scales the page layer so the rect fits the viewport within 24 px margins at a scale of at most 3×, crossing page boundaries; no duration and no spring means a cut. `cameraRect` in state. `Offset pageToViewport(int page, double x, double y)` and `(int page, Offset fraction) viewportToPage(Offset point)` map page fractions to viewport logical px and back, current every frame while scrolling, zooming or moving the camera (from the engine's page extents, scroll offset, zoom and camera matrix). Pure maths in `camera.dart` (`Matrix4 fitRect(Rect rectPx, Size viewport, {double margin = 24, double maxScale = 3})`, `List<Rect> tallPanelSteps(Rect rectPx, Size viewport)` walking a panel taller than the viewport in steps of 75 % of the viewport height) with a test. Add `ReaderLayout.guided` to mobile/13's `setLayout`: one page at a time on the paged stage, the page layer driven by the camera's `Matrix4` through a `Transform`, and the engine's `guidedActive` flag (read by mobile/12's iOS back-swipe rule) true while it is on.
A6. **Auto-scroll model** (on top of mobile/12's `autoScrollPxPerSecondX`), pure functions in `auto_scroll_model.dart` with tests:
   - Manga: `px/s = 60 × speed × viewportHeight / 1080` (an 844 px phone at 1.00× scrolls 46.9 px/s; 3.00× at 1080 px gives 180 px/s); speed 0.50–3.00 in 0.05 steps.
   - **Ramp**: every change of the effective speed (start, a speed step, a pace change) eases from the current rate to the new one over a `ramp` duration along a `rampCurve` (the skin passes 400 ms `durGlide` and `CineCurves.settle` = `Cubic(0.16, 1, 0.3, 1)`); integration stays elapsed-time based through the engine's `Ticker` with long frames clamped as today, so dropped frames never change the pace.
   - **Pace by dialogue**: `paceFactor(int words) = clamp(1.2 − words / 60, 0.5, 1.0)` (the `scalarPace*` tokens: 12 words or fewer → 1.0, 42 words → 0.5, a wordless page → 1.0); recomputed every 250 ms and eased over the ramp; applies only when the chapter has dialogue text.
   - **Interruption**: a touch pauses; its release resumes after 800 ms when "Resume after I let go" is on; a manual drag scroll pauses and stays paused; the chrome stays hidden.
   - **Boundaries**: in continuous mode it rolls through seams and read-all dividers, pausing only at the `CH 143 IS ON ITS WAY` band (mobile/12) and resuming when its pages land; at the series' end it stops, emits `autoScrollEnded` and the skin shows the chrome.
   - **States**: `off | running | paused`; the toggle goes `running` ↔ `paused` (from `off` it starts); leaving the reader, switching to a paged layout, a navigated chapter change or the series' end set `off`. Nothing here starts it by itself.
A7. **Novel pace** (`mobile/lib/features/novels/utils/novel_pace.dart` + test): the profile's pace is the median, over its last 10 completed novel chapters, of `word_count / (time_spent_seconds / 60)`, counting only chapters with 60 ≤ `time_spent_seconds` ≤ 7200 and a pace of 80–900 wpm, and 250 wpm until 3 samples exist; stored in SharedPreferences per profile under `mm.novel-pace.u{user}p{profile}` as `{samples: [{chapter_key, wpm}]}` (at most 10), recomputed on each chapter completion from the seconds the reading clock pushed for that chapter and the chapter's word count (counted from the text the reader laid out); `novelPxPerSecond(paceWpm, speed, lineHeightPx, avgWordsPerLine) = (paceWpm × speed / 60) × lineHeightPx / avgWordsPerLine`, where `avgWordsPerLine` = the laid-out chapter's word count ÷ its rendered line count (from mobile/14's paragraph layout), recomputed after any Type sheet change.
A8. **Preference fields** (only where mobile/12, mobile/13, mobile/14 or mobile/18 did not create them; grep first and reuse their names): per profile in the manga reader record `soundscape` (`off | match | <loop id>`, default `off`), `pauseSoundscapeForNarration` (false), `paceByDialogue` (false), `pageTint` (true), `resumeAfterRelease` (true), `guidedAutoAdvance` (`{on: false, mode: PACE_BY_WORDS | FIXED, fixedMs: 3500}`); the same `soundscape` field in the novel settings record; per series `autoScrollSpeedX` (manga, exists) and per book `autoScrollSpeedX` in the novel preferences map; per device `mm.reader.device.soundscapeVolume` (default 0.40). C1. **Files and cache** (skin-neutral, so Glass's `mobile/44` extends it): `mobile/lib/features/reader/services/soundscape_files.dart`: `Future<File> soundscapeFile(String id)` downloads `{API base}/app/soundscapes/{id}.{ext}` once through the app's Dio client into `getApplicationSupportDirectory()/soundscapes-v1/` (the cache name backend/07 documents; bump it when a recording changes) and returns the cached file afterwards; `ext` is `m4a` on iOS and `ogg` on Android (§9.4.2 Formats); ids `projector-room, rain-on-glass, night-city, cafe, night-wind, low-drone, afternoon-park, temple-bells`; `isCached(id)`; a partial download is written to a temporary name and renamed when complete. Test on a fake Dio adapter and a temporary directory.
C2. **The player** (`house_sound.dart`, a Riverpod `Notifier` used by both readers): a second `just_audio` `AudioPlayer(handleAudioSessionActivation: false)` with `setLoopMode(LoopMode.one)` on the cached file, **not** `flutter_soloud`: §9.4.2 and the §6 State A row name the `just_audio` player for Cinematic's soundscape (the plan entry for this step says `flutter_soloud`; DESIGN.md wins; say so in the report). The player requests no audio focus, so it mixes with the user's music at its own volume, never ducking or stopping it. Fades are volume ramps driven by a `Ticker` (linear): in over 2000 ms, out over 600 ms; `setLoop(id | null)` cross-fades (old out over 600 ms, new in over 2000 ms); `setVolume(v)`; `duck(bool)` ramps to 30 % of the volume (or back) over 300 ms; `pause()` / `resume()` with those fades. While a loop plays, call `skin_audio.dart`'s `setSoundscapeActive(true)` (add it if missing) so UI cues are suppressed (§6).
C3. **Audio session** (§6): the soundscape runs in State A (`.ambient` + `mixWithOthers`, no Android focus) when no narration is active, and continues under State B while narration plays, at 30 % player volume, or paused when "Pause the soundscape during narration" is on (the switch mobile/18 shows). `skin_audio.dart` stays the only place that configures `AudioSession.instance`.
C4. **Choice**: `OFF`, `MATCH THE MOOD` or a loop id, per profile (A8), volume per device. `MATCH THE MOOD`: pure `matchTheMood(List<String> genres, Mood mood)` in `soundscape_match.dart` + test: case-insensitive, the series' genres in order, the first that appears in: Romance, Josei, Shoujo → Rain on glass; Action, Martial Arts, Murim, Sports → Low drone; Comedy, Slice of Life, School → Café; Horror, Thriller, Mystery, Psychological → Night wind; Fantasy, Isekai, Regression, Cultivation, Historical → Temple bells; Drama, Crime, Sci-Fi → Night city; Adventure, Seinen → Afternoon park; no match → the profile mood's default (default Projector room, romantic Rain on glass, action Low drone, comedy Café, horror Night wind, slice_of_life Afternoon park, fantasy Temple bells).
C5. **Lifecycle**: with a soundscape set, the loop fades in over 2000 ms when a reader opens; it fades out over 600 ms on leaving the reader and on `AppLifecycleState.paused` (and resumes with the 2000 ms fade on `resumed`); under narration it ducks or pauses per C3.
C6. **Picker rows** (the manga setup sheet's AMBIENT tab, the novel Type sheet's `AMBIENT` group, and mobile/18's Settings → Ambient, which already has the rows without `Hear`): `OFF`, `MATCH THE MOOD`, then the eight loops as a radio group (`Semantics(inMutuallyExclusiveGroup: true, checked: …)`), each row the name in `type.title`, the one-line description in `type.caption` (Projector room "A soft hum with distant reel ticks.", Rain on glass "Steady rain on a window.", Night city "Distant traffic after dark.", Café "Low voices and cups.", Night wind "Wind across an empty street.", Low drone "A deep, even hum.", Afternoon park "Birds and far-off voices.", Temple bells "Slow bells over a quiet courtyard.") and a `Hear` (`secondary` sm, 44 / 48 hit): it pauses the running loop (600 ms fade), switches `skin_audio` to the Voice-sample state (§6: `.playback` with `.duckOthers`, `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`), plays 5 s of the chosen loop (300 ms fade in, fading out over the last 600 ms), restores the previous state and resumes the running loop (2000 ms fade in); one preview at a time. While fetching, `Hear` shows a 16 px leader dial after 400 ms; offline and not cached, the row's caption reads "Available when you're online." and `Hear` is disabled. Then the volume slider 0–100 % (§7.20, per device). Insert this `Hear` into the trailing slot `mobile/18` left on each Settings → Ambient loop row (`mobile/18` builds no preview player; if an earlier session built one anyway, point the rows at this preview and delete the duplicate player when nothing else imports it).
C7. **Indicator**: a 16 px `waveform` glyph while a loop plays: in the manga running head right after the chapter folio's `caret-down`, inside the title group, with its own 44 / 48 hit (not one of the four trailing buttons), tooltip and semantics "House sound: Rain on glass", opening Reading setup at `AMBIENT`; in the novel top bar's title area, opening the Type sheet at its `AMBIENT` group.
C8. Haptics: none for the soundscape.

### D. The guided view (§9.4.3; `mobile/lib/skins/cinematic/screens/reader/guided_view.dart`)

D1. **Entry**: the setup sheet `LAYOUT` segmented control gains `GUIDED` (`STRIP │ SINGLE │ DOUBLE │ GUIDED`, per series; hidden in read-all); hardware `u` toggles guided view (back to the series' previous layout); a `panel-focus` button joins the running head's trailing list once `panels[currentPage]` is a non-empty list (at its place in `mobile/12` F4's order, right after bookmark; phones show at most four: download mark, bookmark, guided view, settings, §8.14.3), Fill plus the 2 px `spot` rule while guided view is on, tooltip and semantics "Guided view".
D2. **Presentation**: the viewport shows one panel scaled to fit within 24 px margins (at most 3×) through `setCamera`; the rest of the page dimmed to 15 % by the `color.matte.guided` matte (black at 85 %), painted by one `CustomPainter` as a full-viewport rectangle with the panel's viewport rect cut out (`Path.combine(PathOperation.difference, …)`), moving with the camera; the panel folio `PANEL 3 / 7 · PAGE 18` bottom-left in `type.folio` `ink.100` on the matte (0.85 black exceeds the 0.60 `ink.100` needs over art); the running head and folio bar behave as in paged mode.
D3. **Moving**: a tap on the right 30 % / a left swipe (72 px or 600 px/s) / hardware `→` / `j` → next panel; the left 30 % / a right swipe / `←` / `k` → previous; the centre 40 % toggles the chrome (all mirrored for right-to-left series). The camera **dollies** between panels: `setCamera(next, duration: context.cine.durRack /* 520 ms */, curve: CineCurves.turn)`, logged as `CineMotion.play('dolly')`; at a page's last panel, next **cuts** to the next page's first panel (`setCamera(…)` with no duration, haptic `page.turn`, sound `turn` if on); after the chapter's last panel the credits page follows whole. Haptic `page.turn` per panel. A double tap shows the whole page: a 320 ms (`durColumn`) zoom out along `CineCurves.turn`, held 1500 ms (`durHoldGlance`), then back to the panel over 320 ms. A pinch overrides the camera until released (mobile/12's `pinchZoom`), then the camera dollies back to the current panel. A panel taller than the viewport is walked in `tallPanelSteps` of 75 % of the viewport; with auto-scroll on, the camera pans down it at the auto-scroll speed. On iOS the back edge swipe is off while guided view is on (mobile/12 reads `guidedActive`).
D4. **Auto-advance** (option "Guided view auto-advance", default off, per profile; also on whenever auto-scroll is started in guided view): each panel holds, then the camera moves on. `PACE BY WORDS` (the default when the chapter has dialogue text): **1.2 s + 0.25 s per OCR word in the panel, capped at 6 s** (`durHoldPanelBase` 1200, `durHoldPanelWord` 250, `durHoldPanelCap` 6000; a wordless panel 1.2 s, 10 words 3.7 s, 20 words 6 s; `panelHoldMs(words, mode, fixedMs)` in `features/reader/engine/guided.dart` with a test); `FIXED`, or no dialogue text: the fixed hold (2–10 s in 0.5 s steps, default 3.5 s). A 2 px `spot` hold rule under the `PANEL 3 / 7` folio fills over the hold (`Curves.linear`). A touch, a key or a manual move pauses auto-advance; `p` or the chip resumes it (the chip reads `▸ AUTO · PACED` or `▸ AUTO · 3.5 S` here). Under reduced motion, and while a screen reader runs (`MediaQuery.accessibleNavigationOf(context)`), auto-advance never starts by itself (§14.1, §14.5), and once started by hand it moves by cuts under reduced motion.
D5. **Setup rows** (AMBIENT): `Guided view auto-advance` switch, then `PACE BY WORDS │ FIXED` (segmented, 40 px) and the fixed-hold stepper 2–10 s (step 0.5, default 3.5), per profile.
D6. **States**: analysing the current page: the page shows whole with the folio `PAGE 18 · FINDING PANELS` on the folio-flag ground (§2.1.4: a `#000000` box, 1 px `ink.100` border, 4 × 8 px padding); no panels found or analysis failed: the page shows whole with `PAGE 18 · WHOLE PAGE` and next moves to the next page; offline: works from the saved copy (stored panels, or local analysis of the saved blobs); reduced motion: cuts instead of dollies.
D7. **Semantics and keys**: the folio is a `Semantics(liveRegion: true)` node ("Panel 3 of 7, page 18"); `u`, `→`/`j`, `←`/`k`, `p` are registered in the reader's key group (mobile/12's `reader_keys.dart`, with the escape order unchanged) and listed in the `?` sheet.

### E. Page-tinted chrome (§9.4.4)

E1. **Applied to**: the reader chrome root (the overlay with the running head, folio bar, ruler and scrims) holds one `TweenAnimationBuilder<Color?>` per role, `page.tint` and `page.light`, derived by mobile/04's `skins/cinematic/tint.dart` from the engine's `pageTint` (the `cover` source derives both from the series cover's `ambient.duo`, fallback `#B8B2A4`).
