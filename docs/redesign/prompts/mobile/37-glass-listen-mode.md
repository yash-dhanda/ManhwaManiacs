# Mobile Glass Listen mode with the 31 voices

Track: mobile · Order 93 · Depends on: `docs/redesign/prompts/mobile/36-glass-novel-reader.md` · Web twin: `docs/redesign/prompts/web/37-glass-listen-mode.md` (may run at the same time in another session; you never touch `frontend/`) · Proof folder: `docs/redesign/proof/mobile-37/`

## Goal

Build Glass Listen mode (glass §8.16) in the Flutter app: narration that keeps playing across the whole Glass app, with the listen row above the novel reader's bottom capsule, the bottom accessory "Now narrating" everywhere else on phones and the desktop accessory at the sidebar's foot on the Flutter desktop frame; the full player (a `?sheet=player` sheet grown out of the row or the accessory, T5 at `medium` and `solid2` at `large`, a 560 px window on the desktop frame, the Listen tab of the novel reader's right panel) with the artwork and its tilt parallax, the speaking orb that takes each speaker's colour, the sentence-ticked scrubber, the transport, the three tiles and the lyrics-style sentence list; the speed dial; the voice orbit for every voice the server has (31 in production) on `SnapPhysics`, whose centred voice introduces itself, and the cast sheet; the Audiobook sheet from the book page; the sleep timer with Glass's shake to extend; highlight-as-read on the page with narration-driven page turns in paged mode; the shared `audio_service` lock screen and notification with the Glass accent `iris600` `#7563F2`; every state and hardware key. Playback, timing, sleep, sessions, saved audio, jobs, casting and voice samples already exist in the skin-neutral data layer from `mobile/15`: this step adds Glass chrome and gestures, makes three behaviours per-skin parameters (stop on leaving the reader, lock-screen controls, the notification accent) and changes no Cinematic behaviour. Listen adds no ScreenId, so the Glass `PENDING` set does not change here.

### A. Skin-neutral data layer changes (first commits, no pixels, Cinematic unchanged)

A1. **Narration survives leaving the reader in Glass.** If `mobile/15` stops narration when the novel reader route unmounts (in the controller, the handler or the Cinematic chrome), move that decision into a parameter: `NarrationController.stopOnReaderExit` (default `true`, so Cinematic is unchanged), which the Glass skin sets to `false` through a provider override in `glass_skin.dart`. The Glass shell watches `narrationControllerProvider` so it stays alive outside the reader. Test both values.
A2. **Lock-screen controls per skin.** `NarrationAudioHandler` takes a `NarrationControlSet` (`cinematic`: `[rewind, play/pause, fastForward, skipToNext]`, compact `[0, 1, 2]`, exactly as `mobile/15` shipped; `glass`: `[skipToPrevious, rewind, play/pause, fastForward, skipToNext]`, compact `[1, 2, 3]`), chosen from the active skin through a provider the skin overrides. Add the `skipToPrevious` handler (the reader's previous chapter through the novel controller). `systemActions` stay `{seek, seekForward, seekBackward}`; rewind and fast-forward stay ±15 s. Handler test with a fake player for both sets.
A3. **Notification accent from the active skin.** `AudioService.init` runs once, in `main()`, before `runApp`, and its `AudioServiceConfig.notificationColor` cannot change afterwards. `main()` already reads the stored skin (`SkinBoot.read()` from `mobile/01`) before it: pass `notificationColor: bootSkin == SkinId.glass ? const Color(0xFF7563F2) : const Color(0xFFF4D03F)` and keep every other config field `mobile/15` set (`androidNotificationIcon: 'drawable/ic_stat_mm'`, channel name `Listen`, 15 s intervals). An in-process skin switch keeps the colour of the skin the process started in until the next cold start; record this platform limit in the report.
A4. **Narration level for the speaking orb.** `just_audio` exposes no audio level. Add `mobile/lib/features/novels/services/narration_level.dart`: when `readSamplesFromMem` exists in `flutter_soloud` 4.1.7, fetch the chapter's `ogg` rendition once (`GET /novels/audio/file?…&format=ogg` with the authenticated Dio client, or the saved file when the saved audio is `ogg`; on iOS the playing `m4a` stays the playback source), call `SoLoud.instance.readSamplesFromMem(bytes, ceil(total_ms / 1000 × 30), average: true)` in the background after playback starts, and keep the resulting 30-per-second envelope in memory for that chapter; otherwise build the envelope from the segment timings (1.0 inside a segment, 0 in the gaps). `levelAt(Duration position)` reads the envelope; the orb smooths it with `voice_pulse.dart` (attack 80 ms, release 240 ms). Until the envelope is ready the orb is static. Test the sampling index maths and the segment fallback.
A5. **Glass shake to extend.** Glass's rule differs from Cinematic's (§8.16.6: threshold 2.2 g over 300 ms, off by default, foreground only). Parameterise `ShakeDetector(thresholdMs2, window, samplingPeriod)` with Cinematic's current values as the defaults; Glass passes `thresholdMs2: 21.57` (2.2 × 9.80665), `window: Duration(milliseconds: 300)` (two peaks above the threshold within 300 ms), `samplingPeriod: Duration(milliseconds: 33)` (30 Hz, §15.7). Glass subscribes to `userAccelerometerEventStream` only while a sleep timer runs, the Glass switch is on and the app is `resumed`, and cancels on `paused`. The Glass switch is a new field `glassShakeToExtend` (default `false`) in the listen settings record `mm.listen-settings.u{user}p{profile}` (the normaliser keeps unknown fields; Cinematic's `shakeToExtend` is never read by Glass). A shake adds 5 minutes, fires `select` (`selection`) and shows the toast "Sleep timer +5 min". Tests with a fake stream: two peaks at 280 ms extend, at 320 ms do not, and nothing subscribes while the timer is off.
A6. **Notification tap.** Listen to `AudioService.notificationClicked.where((clicked) => clicked)` in the Glass shell and push `Routes.novel(sourceId, seriesKey, chapterKey, listen: true)` for the playing chapter, unless that chapter's reader is already the top route; a reader opened this way with nothing beneath follows `mobile/36`'s Nothing beneath rule.

### B. Pure Glass helpers (`mobile/lib/skins/glass/listen/`, each with a test under `mobile/test/skins/glass/listen/`)

B1. **`voice_hue.dart`:** `voiceHue(double pitchHz)` = OKLCH(L 0.80, C 0.12, h) with `h = 250 − (clamp(pitchHz, 80, 300) − 80) / 220 × 210` (deep voices blue-violet at 250°, bright voices warm at 40°), converted to sRGB with the chroma reduced in 0.01 steps until in gamut. The test asserts ≥ 9:1 against `#000000` at 80, 190 and 300 Hz and, when `frontend/src/skins/glass/listen/voice-hue.test.ts` exists, the same three hex values it asserts. §8.16 uses "the voice's hue" without a rule; this is the web twin's rule; name it in the report.
