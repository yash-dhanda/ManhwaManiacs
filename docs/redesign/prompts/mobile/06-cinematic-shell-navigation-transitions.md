### 4. Pages and transitions (`transitions.dart`, `wipe_geometry.dart`, `shutter.dart`, `navigation.dart`, `screens/reader/reader_route_page.dart`)

4.1 **Page** (§4.5, §8.0.5 "Route transitions in the app"): incoming x +24 → 0 px and opacity 0 → 1 over 320 ms `settle`; outgoing (via `secondaryAnimation`) x 0 → −24 px and opacity 1 → 0 over 224 ms (`durPageOut`) `lift`; a pop reverses both over 224 ms. Reduced: a 150 ms opacity cross-fade.
4.2 **iOS**: every pushed route is a `SwipeablePage` (`swipeable_page_route` 0.4.8) with `canOnlySwipeFromEdge: true`, `backGestureDetectionWidth: 20`, `transitionDuration` 320 ms (480 ms for match cuts, 440 ms for Dip pages), `reverseTransitionDuration` 224 ms (336 ms `durMatchBack` for match cuts, 440 ms for Dip pages) and a `transitionBuilder` that paints the page's transition when `isSwipeGesture` is false and, when true, **the finger-tracked slide**: the top page's x follows the finger on a linear curve while the page beneath goes from −30 % to 0 under a `#000` dim falling from 0.6 to 0 (the page beneath reads `Navigator.of(context).userGestureInProgress`, because its own `isSwipeGesture` is false); release is the package's own `Curves.fastLinearToSlowEaseIn` (hard-coded in 0.4.8's `dragEnd`); commit past 50 % or ≥ 1 width/s (the package's rule). The package is not forked. Export the slide painter as `CineSwipeSlide` (mobile/12 reuses it).
4.3 **Android**: `CinePageTransitionsBuilder extends PageTransitionsBuilder` overrides `transitionDuration` (320 ms) and `reverseTransitionDuration` (224 ms); its widget is a `WidgetsBindingObserver` that copies Flutter's private `_PredictiveBackGestureDetector` (from the SDK file found in Read first 9): `handleStartBackGesture` returns false for `backEvent.isButtonEvent` or when `!(route.isCurrent && route.popGestureEnabled)`, otherwise calls `route.handleStartBackGesture(progress: 1 − backEvent.progress)`; `handleUpdateBackGestureProgress`, `handleCommitBackGesture` and `handleCancelBackGesture` forward the same way. When `route.popGestureInProgress` is false it paints Page; when true the **fade-through**: the outgoing page's scale 1.00 → 0.95 and opacity 1 → 0 over progress 0–0.6, the incoming page's opacity 0 → 1 over progress 0.4–1.0, a commit finishing in 240 ms `settle` and a cancel returning in 160 ms `settle`. `ZoomPageTransitionsBuilder` and `PredictiveBackFullscreenPageTransitionsBuilder` never ship.
4.4 **Match cut** (§4.5, §8.0.4): `CineMatchCutPage` (Android: a `Page` whose `PageRoute` uses 480 / 336 ms with the same builder; iOS: the `SwipeablePage` above with 480 / 336 ms) with the destination's cover a `Hero` whose tag is the `(sourceId, seriesKey)` record, `transitionOnUserGestures: defaultTargetPlatform == TargetPlatform.iOS` (iOS reverses the match cut with the finger; Android's predictive back fades through), `createRectTween: (a, b) => RectTween(begin: a, end: b)` and the route animation curved with `CineCurves.turn`; everything else dissolves (the incoming page's opacity over 240 ms).
