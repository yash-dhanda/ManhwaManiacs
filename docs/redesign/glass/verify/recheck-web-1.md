# Recheck round 1: Glass web lens (`judge-web.md`, section "Confirmed")

Method: for each of the 21 confirmed findings I checked that `glass/DESIGN.md` contains the final fix as the judge wrote it (reading the edited sections in full, not only the lines `fixed-web.md` names), grepped for the old values that the fix should have removed, and grepped for every other place the changed value or rule is repeated to look for contradictions. `DESIGN.md` was being edited by the other lenses' fix rounds while I worked (it grew from 4,304 to 4,552 lines), so I re-ran every anchor grep on the live file at the end. Section numbers are authoritative; line numbers are from the 4,552-line state and may have moved.

Result: **17 resolved, 4 unresolved** (WEB-4, WEB-5, WEB-9, WEB-13). In all four the fix itself is in place. What remains in each is one sentence elsewhere in the file that repeats the old rule and now contradicts it; each needs a one-line edit.

## What each unresolved finding still needs

- **WEB-4.** In §8.17 **Grid** and in the §11 "Pinch the grid" row, keep "2 ↔ 3 ↔ 4 ↔ 5 columns and List" for phones only. On tablet and desktop (pinch or Ctrl/⌘ + wheel), the gesture should step Comfortable (`--grid-min` 152, tablet 148) ↔ Compact (112) ↔ List, and the columns then follow §7.8.
- **WEB-5.** In §9.4.2 **Entry**, change "desktop the right panel's Settings tab" to "desktop: inside a reader, the reader's right panel (Settings tab); elsewhere the 440 px right panel (§7.10)".
- **WEB-9.** Pick one total. Either:
  - (a) the fill runs 1000 ms after the 200 ms start, so the total stays 1200 ms as the judge wrote, §4.6 and `threshold.holdConfirm` stay, and the §4.10 **Hold fill** row becomes 1,000 ms; or
  - (b) keep the 1200 ms fill, and change the §4.6 row to "200 ms start + 1200 ms fill (1400 ms)", with §7.25's "(1200 ms …)" updated to match.

  In both cases, add the 200 ms start and 8 px slop to §4.6 and §2.8.5 (for example `threshold.holdStart` 200 ms and `threshold.clickSlop` 8 px), and say that a release before 200 ms after 8 px or more of movement cancels without an action.
- **WEB-13.** In the §11 "Long-press text" row, change the Mobile web cell from "Same" to "Native selection and toolbar (Copy); Bookmark · Play from here · React · Recommend in the bottom action capsule (§8.15.3)".

## Observations (not blocking, outside the web findings' final fixes)

- **O1 (WEB-1 wording).** The §8.0.3 `recap` row (l. 2170) says "a deep link opens the series sheet first, then the recap sheet over it". §15.2's hard-load rule and §8.12 ("a deep link without a parent renders the same layout as a full page") say the series renders as a full page with the recap sheet over it. This predates WEB-1, but changing "series sheet" to "series page" would align them.
- **O2 (WEB-2 neighbour).** The §8.0.1 Tablet row (l. 2122) places the accessory "as a floating capsule bottom-centre of the content column". §7.16 says the collapsed sidebar shrinks the desktop accessory to a 56 px orb (l. 1802), and 768–1023 px is a collapsed-sidebar width. Both statements predate the fix, but one of them should name the tablet case.
- **O3 (WEB-16 neighbour).** At rest, §7.8 puts both the status tag and the 18+ capsule top-left. §8.17 also shows the favourite star at rest when a series is favourited (l. 2857), and no rest position is given for it. The hover rule places the star top-left. The fix covers hover, focus and select mode; the rest-state order of these three marks is still unspecified.
- **O4 (WEB-8).** `KeyX` is named as an `event.code` example, but no `alt+x` binding exists. It is harmless. Because `allowInInput` is exactly `mod+k`, `mod+b` and `Esc`, the Ask box's `alt+1`–`alt+3` examples (§9.1.2) work only when focus is outside the box. That is consistent with the rule, but §9.1.2 could say so.
